# 02. Qodo와 CodeRabbit이 공식적으로 잘한다고 말하는 것

> 이 문서는 예비시험 때 모은 자료야. 서비스 설명은 바뀔 수 있으므로 본시험 시작 전에 공식 문서에서 다시 확인해.

이 문서는 **두 회사의 홍보 문구를 그대로 믿지 않고 실제로 확인할 질문으로 바꾼 문서**야.

기준일: 2026-09-03

## 왜 먼저 적었나

결과를 본 뒤 비교 기준을 만들면 원하는 제품에 유리하게 바꿀 수 있어.

그래서 먼저 회사의 주장을 적고, 그다음 실제 코드로 확인했어.

```text
회사가 잘한다고 말한 내용 수집
↓
실제로 확인할 질문으로 바꿈
↓
같은 Flask 코드로 시험
↓
제품 댓글과 테스트 결과로 확인
```

## Qodo가 잘한다고 말하는 것

| Qodo의 주장 | 쉬운 뜻 | 우리가 확인할 것 |
|---|---|---|
| 여러 역할의 AI가 함께 리뷰 | 버그·보안·설정 등 여러 관점에서 본다는 뜻 | 종류가 다른 버그도 골고루 찾는가 |
| 저장소 전체 내용과 과거 PR을 참고 | 바뀐 줄만 보지 않고 주변 코드도 본다는 뜻 | 변경 줄 밖의 원인까지 연결하는가 |
| 실제 문제는 많이 찾고 틀린 경고는 줄임 | 중요한 버그를 놓치지 않고 정상 코드는 건드리지 않는다는 뜻 | 버그를 찾는 수와 잘못된 경고 수가 모두 좋은가 |
| 중요한 문제를 먼저 보여줌 | 사소한 말보다 장애가 되는 문제를 우선한다는 뜻 | 실제 버그가 쓸데없는 말에 묻히지 않는가 |
| 원인과 고치는 방향을 설명 | 문제라고만 하지 않고 왜 그런지 알려준다는 뜻 | 원인·문제가 생기는 조건·결과를 모두 말하는가 |

- [Qodo 제품 설명](https://docs.qodo.ai/)

## CodeRabbit이 잘한다고 말하는 것

| CodeRabbit의 주장 | 쉬운 뜻 | 우리가 확인할 것 |
|---|---|---|
| 실행 중 오류와 논리 문제를 찾음 | 문법뿐 아니라 실제로 실행할 때 깨지는 문제도 본다는 뜻 | 특별한 입력에서만 생기는 버그를 찾는가 |
| 저장소 전체 내용을 보고 제안 | 바뀐 줄과 연결된 다른 코드도 본다는 뜻 | 호출하는 코드와 설정까지 연결하는가 |
| AI와 기존 검사 도구를 함께 사용 | 생각해서 찾는 방식과 정해진 규칙 검사를 함께 쓴다는 뜻 | 단순 규칙 밖의 Flask 고유 버그도 찾는가 |
| 댓글에서 바로 적용할 수정 코드를 제공 | 설명만이 아니라 실제 코드를 줄 수 있다는 뜻 | 그 코드를 적용하면 모든 테스트가 통과하는가 |
| 새로 바뀐 코드에 집중 | 이미 본 문제를 반복하지 않는다는 뜻 | 다시 리뷰할 때 새 문제만 말하는가 |
| 팀이 알려준 규칙을 기억 | 팀의 선택을 다음 리뷰에도 반영한다는 뜻 | 같은 규칙을 다른 코드에서도 지키는가 |

공식 출처:

- [CodeRabbit PR Review 설명](https://docs.coderabbit.ai/overview/pull-request-review)
- [CodeRabbit 코드 리뷰 설명](https://docs.coderabbit.ai/guides/code-review-overview)
- [CodeRabbit 제품 설명](https://docs.coderabbit.ai/index)

## 둘 다 공통으로 말하는 것

```text
주변 코드까지 이해함
버그를 잘 찾음
쓸데없는 경고를 줄임
고칠 방법을 알려줌
팀 규칙을 기억함
```

말만 보면 두 제품이 거의 같아 보여.

그래서 실제 시험에서는 이렇게 나눠서 확인했어.

| 시험 | 확인한 능력 |
|---|---|
| P01 | 특이한 입력값을 처리하는 능력 |
| P02 | 오류가 난 뒤에도 남은 작업 순서를 따라가는 능력 |
| P03 | 사용자가 직접 정한 값과 기본값의 우선순위를 이해하는 능력 |
| P04 | 파일 이름의 대문자·소문자 차이를 처리하는 능력 |
| C01·C02 | 정상 코드를 버그라고 잘못 말하지 않는 능력 |
| 코드 수정안 | 실제 적용했을 때 완전히 고치는 능력 |
