# 02. 기존 예비시험의 한계 — 작은 결과를 최종 결론으로 착각하지 않으려고

## 결론부터

P01~P04와 C01~C02는 **예비시험**이야. 결과는 보관하지만 본시험 점수에는 넣지 않아.

## 왜 예비시험인가

1. 버그가 4개뿐이라 우연의 영향이 커.
2. 대부분 바뀐 코드가 작아서 큰 PR을 리뷰하는 능력을 알 수 없어.
3. P02와 P04에는 나중에 서로 다른 문제가 함께 생긴 것을 확인했어.
4. 정답과 과거 수정 내용이 같은 저장소와 Git 기록에 남아 있어.
5. 제품별로 한 번만 실행해서 결과가 반복되는지 알 수 없어.

## 현재 저장소에서 실제로 발견한 정답 단서

| 발견한 곳 | 무엇이 보이는가 | 본시험 처리 |
|---|---|---|
| `benchmark/oracles/pilot-2026-09-03/` | 예비시험 정답 테스트와 추가 확인 테스트 | 실행 저장소에 넣지 않음 |
| `benchmark/`의 압축 자료와 Git 묶음 | Flask의 과거 이슈, PR, 수정 기록 | 관리 저장소에만 둠 |
| `CHANGES.rst`, `docs/changes.rst` | 과거에 무엇을 고쳤는지 설명 | 실행 저장소에서 제거 |
| `실험-케이스/`, `실험-결과/` | 문제의 원인과 두 제품의 답 | 실행 저장소에 넣지 않음 |
| README와 비교 문서 | P01~P04의 정답과 결과 | 실행 저장소에 넣지 않음 |
| Git 기록과 참조 이름 | `fix`, 문제 번호, 예비시험 브랜치, 과거 PR | 새 Git 기록으로 다시 시작 |

이 표로 현재 저장소를 그대로 본시험장으로 쓸 수 없다는 것을 알 수 있어.

## Git 기록 검사 결과

- 로컬 Git 참조: 8,817개
- `case/pilot/`, `control/pilot/`, `run/pilot/` 이름이 남아 있음
- Flask 과거 수정 커밋과 복원한 PR 참조가 함께 있음
- P01~P04에 넣은 변경과 정답을 고친 커밋을 따라갈 수 있음

따라서 파일 몇 개만 지우는 것으로는 부족해. **깨끗한 새 저장소에서 짧은 새 Git 기록으로 시작해야 해.**

## 다시 쓸 수 있는 자료

- 현재 `src/`의 Flask 코드
- 현재 `tests/`의 공개 테스트
- 과거 이슈와 합쳐진 PR 자료
- 예비시험에서 만든 수집 방법과 판정 경험
- 제품 댓글 원문과 수정 코드 확인 결과

## 본시험에서 빼야 하는 자료

- 예비시험 정답 파일
- 과거 이슈와 PR 압축 파일
- 변경 기록 문서
- 경쟁 제품 이름이 든 설정 파일
- 실험 계획, 결과, 문제 설명 문서
- 전체 Flask Git 이력과 복원한 수천 개의 참조

## 실제로 실행한 확인

현재 정상 코드에서 다음을 확인했어.

| 확인 | 결과 |
|---|---|
| Flask 공개 테스트 전체 | 494개 통과 |
| 제품에 보여주지 않았던 예비시험 정답 테스트 | 6개 통과 |
| 정답 보관 예정 폴더가 Git 저장소 안인지 | Git 저장소 밖 |

이 결과는 현재 기준 코드가 정상이며, 예비시험 정답 테스트도 현재 코드에서는 모두 통과한다는 뜻이야.

## 사전 검사 판정

- 현재 저장소를 자료 보관소로 쓰기: 가능
- 현재 저장소에서 본시험 실행하기: 불가
- 기존 예비시험 결과를 방향 참고용으로 쓰기: 가능
- 기존 예비시험 결과를 최종 점수에 넣기: 불가

딱 기억해.

**예비시험은 버리지 않지만, 최종 성적표에는 넣지 않아.**
