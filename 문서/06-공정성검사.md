# 06. 공정성 검사 — 실험이 깨진 일을 제품 실패로 계산하지 않으려고

## PR을 열기 전

- [ ] 두 PR의 시작 코드가 같음
- [ ] 두 PR에 같은 커밋을 사용함
- [ ] 파일 목록과 바뀐 줄 수가 같음
- [ ] 변경 내용 지문이 같음
- [ ] 제목과 설명이 같음
- [ ] 원본 이슈 번호와 정답 설명이 없음
- [ ] 정답 테스트가 저장소 밖에 있음
- [ ] 첫 PR에는 Qodo만, 둘째 PR에는 CodeRabbit만 실행됨
- [ ] 두 제품의 읽기와 댓글 권한이 같음

## 리뷰 중

- [ ] 정한 순서대로 리뷰를 요청함
- [ ] 사람이 먼저 힌트 댓글을 쓰지 않음
- [ ] 한쪽 PR에만 새 커밋을 넣지 않음
- [ ] 한 제품이 상대 제품 댓글을 볼 수 없음
- [ ] GitHub와 제품 실행 상태를 저장함

## 리뷰가 끝난 직후

- [ ] PR, 변경 코드, 리뷰, 댓글, 검사 결과를 JSON으로 저장함
- [ ] 제품이 테스트를 실행했다면 그 증거를 저장함
- [ ] 시작과 완료 시간을 원본 자료에 저장함
- [ ] 정답을 열기 전에 원본 저장을 끝냄

## 점수에서 빼야 하는 상황

| 상황 | 처리 |
|---|---|
| 제품이 아예 실행되지 않음 | 제품 실패가 아닌 실행 실패로 분리 |
| GitHub나 테스트 환경 장애 | 다시 실행하거나 제외 |
| 사용량 제한 | 해당 실행을 제외하고 별도 기록 |
| 제품별 권한 차이 | 조건을 맞춘 뒤 다시 실행 |
| 쌍둥이 코드가 다름 | 해당 쌍 제외 |
| 정답이 노출됨 | 해당 문제 폐기 또는 완전히 새로 구성 |
| 사람이나 상대 제품이 답을 먼저 남김 | 해당 실행 제외 |
| 정답 테스트 결과가 흔들림 | 문제를 고친 뒤 처음부터 다시 실행 |
| 원본 버그가 제대로 재현되지 않음 | 후보에서 제외 |

이 표로 제품이 못한 것과 우리가 시험을 잘못 만든 것을 구분할 수 있어.

## 즉시 중단 조건

같은 잘못이 다음 묶음에도 영향을 줄 수 있다면 새 PR 생성을 멈춘다. 원인을 고치고 이미 만든 PR까지 다시 검사한 뒤에만 계속한다.

## 이번 실행 범위

| 확인할 것 | 현재 계획 또는 상태 |
|---|---|
| 실행 저장소 | 현재 `qodo-coderabbit-benchmark` |
| 실제 결함 | 4개 |
| 정상 코드 | 2개 |
| 전체 PR | 12개 |
| 제품 분리 | 쌍둥이 PR마다 다른 제품 명령 사용 |
| 정답 단서 | 현재 저장소에 있으므로 내부 비교로 표시 |

12개를 넘는 추가 PR은 만들지 않는다.

## 비용 확인

비공개 저장소에서는 현재 구독과 사용량에 따라 비용이 달라져서 아직 정확한 금액을 확정할 수 없어.

- [Qodo 공식 가격](https://www.qodo.ai/pricing/): 14일 체험 뒤에는 계속 무료인 비공개 저장소용 요금제가 없고, PR 크기와 복잡도에 따라 크레딧을 사용해.
- [CodeRabbit 공식 가격](https://www.coderabbit.ai/pricing): 비공개 저장소 리뷰는 유료 요금제 대상이며, 시간당 실행 한도와 한도를 넘긴 파일별 추가 요금이 있어.

사용량 제한이 생기면 새 PR을 늘리지 않고, 이미 만든 12개 안에서 재검토를 기다린다.

딱 기억해.

**제품이 안 돈 것, 시험이 깨진 것, 제품이 버그를 놓친 것은 서로 다른 결과야.**
