# 07. 통계와 결론 범위 — 작은 차이를 큰 사실처럼 말하지 않으려고

## 기본 숫자

제품마다 다음 값을 계산한다.

- 정확히 찾은 수 / 전체 버그 수
- 정확히 또는 일부 찾은 수 / 전체 버그 수
- 정상 코드에 잘못 경고한 수 / 전체 정상 코드 수
- 바뀐 1,000줄당 잘못된 경고 수
- 원인, 생기는 조건, 사용자 결과를 각각 맞힌 비율
- 적용 가능한 수정 코드를 준 비율
- 수정 코드가 들어간 비율
- 정답 테스트까지 통과한 비율
- 원래 되던 기능을 깨뜨린 비율
- 처음 맞는 지적까지 걸린 시간
- 전체 리뷰 완료 시간
- 반복시험에서 같은 결과를 낸 비율
- 제품이 실행되지 않은 비율

## 결과를 나눠 보는 기준

- 작은·중간·큰 PR
- 쉬운·중간·어려운 문제
- 문제 종류
- 바뀐 파일 수
- 한 파일 문제와 여러 파일 문제
- 공개 테스트에 단서가 있는 문제와 없는 문제

## 숫자를 보여주는 방법

- 비율만 쓰지 않고 “4개 중 3개”처럼 분자와 분모를 함께 씀
- 시간은 평균보다 가운데 값을 먼저 보여줌
- 95% 신뢰구간을 함께 표시
- 같은 문제의 쌍둥이 PR끼리 직접 비교
- 찾음과 못 찾음의 차이는 McNemar 정확 검정 사용
- 시간 차이는 가운데 값과 다시 뽑아 계산한 신뢰구간 사용
- 사례가 적은 칸은 “표본이 적어 결론을 내릴 수 없음”이라고 씀

## 반복시험

RETRO PR 12개에는 반복시험을 추가하지 않았다. 아래 기준은 새 50개 PR 실험의 반복 문제에 사용한다.

| 결과 | 뜻 |
|---|---|
| 3번 모두 찾음 | 안정적으로 찾을 가능성이 높음 |
| 2번 찾음 | 대체로 찾지만 흔들림 |
| 1번 찾음 | 우연일 가능성을 확인해야 함 |
| 3번 모두 못 찾음 | 반복되는 약점 후보 |
| 정상 코드에서 경고 반복 | 반복되는 잘못된 경고 후보 |

이 표로 한 번 맞힌 결과와 계속 맞히는 능력을 구분할 수 있어.

## 허용되는 결론

“이번 Flask 결함 4개에서 Qodo는 X개, CodeRabbit은 Y개를 정확히 찾았다”처럼 시험한 범위만 말한다.

## 허용되지 않는 결론

- 한 제품이 항상 더 좋다.
- 모든 언어와 프로젝트에서도 같은 결과가 난다.
- 두 제품은 어떤 종류의 문제도 전혀 찾지 못한다.
- SH Solution이 이미 두 제품보다 뛰어나다.

딱 기억해.

**숫자는 시험한 Flask 문제만 설명하고, 시험하지 않은 세상까지 설명하지 않아.**
