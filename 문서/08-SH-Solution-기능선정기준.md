# 08. SH Solution 기능 선정 기준 — 반복되는 공통 빈틈만 제품으로 만들려고

## SH Solution은 무엇인가

SH Solution은 Qodo나 CodeRabbit을 그대로 따라 만드는 세 번째 리뷰 봇이 아니야.

두 제품의 리뷰와 수정 코드가 실제 문제를 고치는지 자동으로 확인하고, 둘 다 반복해서 놓친 문제를 저장소 전용 검사로 바꾸는 도구야.

## 기능 후보가 되려면

다음을 모두 만족해야 해.

1. 서로 다른 새 결함 사례가 3개 이상
2. Qodo와 CodeRabbit이 각각 절반 이상 놓침
3. 서로 다른 코드 영역 두 곳 이상에서 나타남
4. 제품이 안 돌아서 놓친 결과가 아님
5. 정답 단서가 없는 실행에서도 반복됨
6. 같은 규칙을 정상 코드에 적용해도 잘못된 경고가 심하지 않음

RETRO의 P02 하나만으로는 이 조건을 만족하지 않아. 새 50개 PR 본시험에서도 이 기준을 통과한 공통 빈틈만 기능 후보가 된다.

## 만드는 순서

```text
두 제품이 함께 놓친 사례 모으기
↓
반복되는 원인 찾기
↓
일부 사례로 기능 만들기
↓
만들 때 보지 않은 사례로 다시 확인
↓
정상 코드에도 잘못 경고하는지 확인
```

## 의미 있는 기능이라고 인정할 조건

- 만들 때 보지 않은 버그의 탐지율이 20%p 이상 좋아짐
- 정상 코드의 잘못된 경고 증가는 5%p 이하
- 기존 공개 테스트를 깨뜨리지 않음
- 특정 이슈 번호나 코드 문장을 외워서 찾지 않음
- 같은 원리의 새로운 코드 모양에도 동작함

조건을 못 맞추면 “아직 검증되지 않은 생각”이라고 적고 제품 기능이라고 부르지 않는다.

## 처음 만들 최소 기능

1. 실제 이슈와 수정 PR에서 다시 시험할 문제를 고름
2. 리뷰 제품이 준 수정 코드를 별도 공간에 적용함
3. 공개 테스트와 제품에 안 보여준 정답 테스트를 실행함
4. 두 제품이 함께 놓친 원인을 묶어 보여줌
5. 반복되는 원인을 새 테스트나 리뷰 규칙 후보로 저장함

대시보드와 자체 AI 리뷰 모델은 자료가 충분히 쌓이기 전에는 만들지 않는다.

## SEP 50개 PR 본시험 적용

확정 기능 후보는 **0개**다. 새 결함 정확 탐지는 Qodo 14/16, CodeRabbit 9/16이었고, Qodo가 어떤 원인 묶음에서도 절반 이상 놓치지 않아 공통 빈틈 조건이 성립하지 않았다.

```text
같은 원인의 새 결함 3개 이상 묶음 확인
↓
두 제품이 각각 절반 이상 놓쳤는지 확인
↓
Qodo가 어떤 묶음에서도 절반 이상 놓치지 않음
↓
공통 빈틈 조건 불충족
```

따라서 이번 본시험 결과로 새 탐지 규칙을 SH Solution 확정 기능에 넣지 않는다. RETRO에서 생각한 설정 연결·실행 순서 규칙도 계속 가설로 두며, 다른 저장소의 새 결함 자료가 기준을 채울 때 다시 판단한다.

CodeRabbit이 SEP-012에서 준 적용 가능한 patch 하나는 숨은 테스트 3/3과 공개 테스트 494개를 모두 통과했다. 하지만 표본이 1개뿐이므로 patch 자동 검증 기능의 일반 성능이 검증됐다고 쓰지 않는다.

딱 기억해.

**SH Solution 기능은 아이디어로 정하지 않고, 두 제품이 여러 실제 문제에서 함께 놓친 증거로 정해.**
