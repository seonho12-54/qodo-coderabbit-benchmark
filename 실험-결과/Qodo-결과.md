# Qodo 실험 결과

> P01~P04와 C01~C02는 예비시험이야. 이 결과는 본시험 점수에서 뺀다.

이 문서는 **Qodo가 어떤 버그를 찾았고 무엇을 놓쳤는지 쉽게 설명하는 결과지**야.

## 10초 결론

- 버그 4개 중 3개를 제대로 찾았어.
- 정상 코드 2개에는 잘못된 경고를 하지 않았어.
- P04에서는 우리가 처음 정한 문제 외에 다른 문제도 하나 더 찾았어.
- 이번에는 바로 적용할 코드 수정안을 주지 않았어.

## 전체 결과

| 시험 | 실제 상태 | Qodo 결과 | 걸린 시간 |
|---|---|---|---:|
| P01 | 버그 있음 | 찾음 | 88초 |
| P02 | 버그 있음 | 핵심 문제는 못 찾고 다른 문제를 찾음 | 68초 |
| P03 | 버그 있음 | 찾음 | 61초 |

| C02 | 정상 코드 | 잘못된 경고 없음 | 19초 |

버그를 제대로 찾은 P01·P03·P04의 가운데 시간은 70초야.

## P01: IPv6 서버 주소 문제

서버 주소가 `[2001:db8::7]:8443`처럼 생겼을 때 생기는 문제야.

```text
IPv6 주소 입력
↓
주소를 첫 번째 콜론에서 잘못 자름
↓
포트 번호를 숫자로 바꾸지 못함
↓
서버가 시작되지 않음
```

Qodo는 원인, 문제가 생기는 입력, 최종 결과를 모두 맞혔어.

- [Qodo가 남긴 실제 댓글](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6174#discussion_r3921152923)

## P02: 종료 신호가 빠지는 문제

정상이라면 프로그램을 정리하다 오류가 나도 마지막 종료 신호를 보낸 뒤 멈춰야 해.

```text
종료 정리 중 오류 발생
↓
마지막 종료 신호 전송
↓
오류를 밖으로 전달
```

버그가 들어간 코드는 마지막 종료 신호를 보내기 전에 멈췄어.

Qodo는 이 핵심 문제를 못 찾았어.

대신 마지막 종료 신호를 받는 코드에서 또 오류가 나면 그 오류가 사라지는 다른 문제를 찾았어. 이 발견 자체는 맞지만, 우리가 미리 정해 둔 핵심 문제를 찾은 것으로 계산하지 않았어.

- [Qodo가 찾은 다른 문제](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6175#discussion_r3921175042)

## P03: 사용자가 직접 켠 설정이 무시되는 문제

```text
기본 설정에서는 OPTIONS 기능을 끔
↓
사용자가 특정 주소에서만 직접 켬
↓
코드가 사용자의 선택을 무시함
↓
OPTIONS 요청이 405 오류로 끝남
```

Qodo는 이 문제를 제대로 찾았어.

- [Qodo가 남긴 실제 댓글](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6176#discussion_r3921189273)

## P04: 대문자가 섞인 파일의 안전 처리 문제

```text
ACCOUNT.HTML 같은 파일 이름
↓
확장자의 대문자와 소문자를 구분해서 비교
↓
HTML 안전 처리가 꺼짐
↓
사용자 입력이 코드처럼 실행될 위험이 생김
```

Qodo는 이 문제를 제대로 찾았어.

또 `.html`처럼 이름이 점으로 시작하는 파일에서도 안전 처리가 꺼지는 다른 문제를 하나 더 찾았어.

- [대소문자 문제 댓글](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6177#discussion_r3921211979)
- [점으로 시작하는 파일 문제 댓글](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6177#discussion_r3921211989)

## 이번 결과로 말할 수 없는 것

- 시험이 6개뿐이라 Qodo가 항상 더 좋다고 말할 수 없어.
- P02에는 서로 다른 문제가 두 개 섞여 있었어.
- 이번 실행에서는 Qodo가 바로 적용할 코드를 주지 않아 코드 수정 능력은 비교하지 못했어.

딱 기억해.

**Qodo는 버그 세 개를 찾고 정상 코드는 건드리지 않았지만, P02의 핵심 문제는 놓쳤고 바로 적용할 수정 코드는 주지 않았어.**
