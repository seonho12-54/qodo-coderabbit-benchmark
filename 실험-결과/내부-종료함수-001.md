# 내부 비교 001 결과: 종료 함수가 중간에 멈추는 문제

> **완전한 블라인드 시험이 아니다.** 이 저장소에는 정답과 과거 수정 기록이 있다. 따라서 이 결과는 제품의 절대 점수가 아니라 같은 코드에서 두 제품이 어떻게 반응했는지 보는 내부 비교다.

## 10초 결론

두 제품 모두 핵심 문제를 찾았다.

- Qodo: 왜 멈추는지와 언제 멈추는지를 정확히 설명했다. 직접 적용하는 코드는 주지 않았다.
- CodeRabbit: 같은 문제를 정확히 설명하고, 원래 코드로 되돌리는 적용 가능한 수정안도 줬다.
- 잘못된 경고: 두 제품 모두 없었다.
- 수정안 테스트: 사용자의 최신 지시에 따라 실행하지 않았다.

## 비교표

| 확인 항목 | Qodo | CodeRabbit |
|---|---|---|
| 문제 원인 | 찾음 | 찾음 |
| 문제가 생기는 조건 | 찾음 | 찾음 |
| 실제로 생기는 결과 | 뒤의 종료 함수가 실행되지 않는다고 설명 | 뒤의 종료 함수가 실행되지 않는다고 설명 |
| 구체적인 사용자 피해 예시 | 없음 | 없음 |
| 잘못된 경고 | 없음 | 없음 |
| 바로 적용할 코드 수정안 | 없음 | 있음 |
| 수정안 테스트 | 확인 안 함 | 확인 안 함 |
| 최종 판정 | 부분 탐지 | 부분 탐지 |

둘 다 원인과 코드 결과는 맞혔다. 하지만 자원 반환 누락, 연결 정리 실패 같은 구체적인 사용자 피해까지 말하지 않았으므로 이 저장소의 엄격한 기준에서는 **부분 탐지**로 판정했다.

## Qodo가 남긴 핵심 원문

> Wrapping the entire callback loop in one `_CollectErrors` context causes an exception from any teardown callback to exit the loop, so later callbacks never run. This breaks the stated behavior that all application teardown callbacks execute before collected errors are raised.

쉽게 말하면 다음 뜻이다.

> 종료 함수 하나에서 오류가 나면 반복문이 끝나서, 뒤에 남은 종료 함수가 실행되지 않는다.

- [GitHub의 Qodo 댓글](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6180#discussion_r3921929052)
- [Qodo 전체 원문 JSON](원본/qodo/내부-종료함수-001/review-comments.json)

Qodo는 별도의 AI에게 수정을 시킬 수 있는 안내문을 줬지만, 바로 적용할 수 있는 코드 조각은 주지 않았다.

## CodeRabbit이 남긴 핵심 원문

> When a teardown callback raises, `_CollectErrors.__exit__` suppresses the exception only after this `with` block exits. The `for` loop therefore stops, and later teardown callbacks do not run.

CodeRabbit이 제안한 수정은 오류 수집기를 다시 각 종료 함수 안쪽에 두는 것이다.

```diff
-        with collect_errors:
-            for func in reversed(self.teardown_appcontext_funcs):
+        for func in reversed(self.teardown_appcontext_funcs):
+            with collect_errors:
                 self.ensure_sync(func)(exc)
```

## 테스트 근거

이번 실행에서는 사용자가 “테스트는 하지 말고 바로 두 PR을 올려 비교하라”고 지시했다. 그래서 제품 수정안을 적용하거나 테스트를 돌리지 않았다.

| 확인 항목 | 상태 |
|---|---|
| PR 두 개의 기준 브랜치가 같은가 | 같음: `main` |
| PR 두 개의 변경 커밋이 같은가 | 같음: `26035247e9da7bf973cc59cef8564ad30f27b9b2` |
| Qodo 수정안 테스트 | 코드 수정안이 없어 실행하지 않음 |
| CodeRabbit 수정안 테스트 | 최신 지시에 따라 실행하지 않음 |

따라서 이번 결과로 확실히 말할 수 있는 것은 **탐지와 설명의 차이**까지다. CodeRabbit 수정안이 실제 테스트를 통과한다고 확정해서는 안 된다.

## 이번 한 건에서 알 수 있는 차이

```text
Qodo
= 문제를 찾고 수정 방향을 설명함

CodeRabbit
= 문제를 찾고 바로 적용할 코드까지 제시함
```

한 건뿐이고 정답이 보일 수 있는 저장소에서 실행했으므로, 어느 제품이 항상 더 좋다는 결론은 내리지 않는다.
