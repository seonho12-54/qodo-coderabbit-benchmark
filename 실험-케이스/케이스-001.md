# P01: IPv6 서버 주소 문제

> 예비시험 사례야. 본시험 점수에는 넣지 않아.

이 문서는 **첫 번째 버그 시험에서 무엇을 바꿨고 두 제품이 어떻게 답했는지 설명하는 문서**야.

## 시험에 사용한 PR

| 제품 | PR |
|---|---|
| Qodo | [#6174](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6174) |
| CodeRabbit | [#6](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6) |

두 PR에는 똑같은 코드 변경이 들어 있어.

## 어떤 코드를 바꿨나

Flask가 서버를 시작할 때 서버 주소와 포트 번호를 읽는 코드를 단순하게 바꿨어.

겉으로 보기에는 작은 코드 정리처럼 보이지만 IPv6 주소에서 문제가 생겨.

## 실제 버그

입력값:

```text
[2001:db8::7]:8443
```

버그 흐름:

```text
IPv6 주소를 첫 번째 콜론에서 자름
↓
포트 자리에 db8::7]:8443이 들어감
↓
숫자로 바꾸지 못함
↓
서버가 시작되지 않음
```

이 문제는 실제 Flask [이슈 #6093](https://github.com/pallets/flask/issues/6093)과 [수정 PR #6096](https://github.com/pallets/flask/pull/6096)을 바탕으로 만들었어.

## 테스트 결과

| 확인한 것 | 결과 |
|---|---|
| 누구나 볼 수 있는 기존 테스트 | 133개 통과 |
| 제품에 안 보여준 정답 테스트 | IPv6 버그가 실제로 나타남 |

기존 테스트만 보면 정상처럼 보이지만, IPv6 주소를 넣는 정답 테스트에서는 서버가 시작되지 않았어.

## 제품 결과

| 제품 | 결과 | 걸린 시간 |
|---|---|---:|
| Qodo | 버그를 제대로 찾음 | 88초 |
| CodeRabbit | 버그를 제대로 찾음 | 219초 |

두 제품 모두 원인, 문제가 생기는 입력, 서버가 시작되지 않는 결과를 맞혔어.

- [Qodo의 실제 댓글](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6174#discussion_r3921152923)
- [CodeRabbit의 실제 댓글](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6#discussion_r3921166594)

딱 기억해.

**P01은 IPv6 주소를 일반 주소처럼 잘못 잘라 서버가 시작되지 않는 버그였고, 두 제품 모두 찾았어.**
