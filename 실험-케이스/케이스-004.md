# P04: 대문자가 섞인 HTML 파일의 안전 처리 문제

> 예비시험 사례야. 본시험 점수에는 넣지 않아.

이 문서는 **네 번째 버그 시험의 내용과 결과를 설명하는 문서**야.

## 시험에 사용한 PR

| 제품 | PR |
|---|---|
| Qodo | [#6177](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6177) |
| CodeRabbit | [#9](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/9) |

두 PR에는 똑같은 코드 변경이 들어 있어.

## 실제 버그

```text
ACCOUNT.HTML 또는 icon.SvG 파일
↓
코드가 확장자의 대문자와 소문자를 다르게 봄
↓
HTML 안전 처리가 꺼짐
↓
사용자 입력이 코드처럼 실행될 위험이 생김
```

이 문제는 실제 Flask [수정 PR #6013](https://github.com/pallets/flask/pull/6013)을 바탕으로 만들었어.

## Qodo가 하나 더 찾은 문제

Qodo는 `.html`처럼 이름이 점으로 시작하는 파일에서도 HTML 안전 처리가 꺼진다고 말했어.

우리가 추가 테스트를 만들어 확인해 보니 실제 문제였어.

- [Qodo가 추가로 찾은 문제](https://github.com/seonho12-54/qodo-coderabbit-benchmark/pull/6177#discussion_r3921211989)

## CodeRabbit 수정 코드는 완전했나

CodeRabbit은 확장자를 소문자로 바꾼 뒤 비교하는 코드를 줬어.

```text
대소문자 문제 3개 해결
기존 테스트 493개 통과
점으로 시작하는 파일 문제는 남음
```

즉 처음 찾은 문제는 고쳤지만, 같은 코드 변경으로 생긴 다른 문제까지 전부 고치지는 못했어.

딱 기억해.

**P04에서는 둘 다 대소문자 문제를 찾았고, Qodo는 다른 문제를 하나 더 찾았으며, CodeRabbit의 수정 코드는 일부만 고쳤어.**
